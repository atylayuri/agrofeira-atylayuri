1. As correções de acessibilidade

Correções de acessibilidade feitas no catálogo e no formulário com Bootstrap
Componente Problema Como se detectou Correção Onde está no código
Botão do menu O aria-label da documentação dá o nome "Toggle navigation", em inglês, numa página em português. Painel Accessibility do F12: depois da troca, o Name é "Menu". Trocar o texto do aria-label. button com navbar-toggler, atributo aria-label="Menu".
Botão de fechar do diálogo O aria-label da documentação é "Close", também em inglês. Painel Accessibility com o diálogo aberto: Name "Fechar". Trocar o texto do aria-label. button com btn-close, dentro do modal-header, atributo aria-label="Fechar".
Título do diálogo A documentação usa h1, mas a página já tem um h1 (o do catálogo), e dois h1 quebram a ordem dos títulos. Recomendação da documentação e conferência da hierarquia dos títulos. Usar h2, com a classe h5 para manter o tamanho. h2 com modal-title h5 e id="detalhe-acai-titulo", no modal-header.
Diálogo (role) O validador lê o HTML sem rodar o script e não aceita aria-labelledby num div sem papel. Erro do validador do W3C sem o role. Escrever o role no arquivo, em vez de esperar o Bootstrap escrevê-lo ao abrir. div com modal fade e id="detalhe-acai", atributo role="dialog".
Mensagens do formulário A classe was-validated é só CSS: o leitor de tela não liga a mensagem ao campo. Painel Accessibility no campo do e-mail: aria-describedby e Description com a frase da mensagem. Dar id a cada mensagem e ligar cada campo a ela com aria-describedby. Os inputs #nome, #email e #termos e os três div com invalid-feedback (nome-erro, email-erro, termos-erro).
Títulos dos cartões Com um h1 no alto da página, os títulos h3 dos cartões pulavam um nível. Validador do W3C e leitura da hierarquia dos títulos. Trocar h3 por h2, mantendo as classes card-title h5. Os sete títulos dentro de article.card, no catalogo-bootstrap.html.

Pendências declaradas, que a marcação não resolve:

  • Foco depois do envio com erro: ele fica no botão "Fazer pedido", e levá-lo ao primeiro campo com erro exige programa meu.
  • O diálogo é só do açaí: trocar o conteúdo conforme o produto exige programa meu.
  • Contraste dos botões de contorno ("Ver detalhes" e "Fechar"): o texto cinza (#6c757d) sobre o creme da página (#F4F1EA) dá 4,16:1, abaixo de 4,5:1; corrigir pede uma cor própria para esses botões.

2. O registro de decisão

Contexto

Preciso escolher como estilizar a AgroFeira daqui em diante, inclusive no React do encontro 11. A folha autoral tem 360 linhas de CSS em seis arquivos, e o catalogo.html usa 13 classes distintas. A versão com Bootstrap usa 61 classes distintas e 41 linhas minhas por cima da folha do framework. O script do Bootstrap pesou cerca de 25 kB transferidos (80,5 kB do arquivo aberto). Sem JavaScript, o menu e o "Ver detalhes" não abriram e o formulário vazio foi enviado (Passo 10).

Opções consideradas

  • Folha autoral: ganha controle total e nenhum arquivo de terceiros (360 linhas minhas); cobra escrever tudo, inclusive menu e diálogo.
  • Bootstrap: ganha menu e diálogo prontos, que a documentação lista entre os componentes que dependem do JavaScript dele (Getting started, Introduction, "JS components"); cobra cerca de 25 kB de script, e sem ele o menu não abre.
  • Tailwind: pelos slides, só traz utilitários e o componente é a marcação que eu monto; o Play CDN é um script só para desenvolvimento.

Decisão

Fico com a folha autoral, inclusive no React. O script do Bootstrap troca classes e atributos dos mesmos elementos que o React monta e remonta, e prefiro não ter dois programas mexendo na mesma página.

Consequências aceitas

  • Terei de escrever em React o menu retrátil e o diálogo, o que dá mais trabalho do que o HTML que o Bootstrap pediu.
  • As seis correções da tabela passam a ser minhas desde o início: nome dos botões, foco preso no diálogo e fechamento com Esc.
  • Manterei as 360 linhas e a ordem das camadas, sem grade nem classes prontas.

O que me faria mudar de ideia

  • Montar o menu e o diálogo em React levar mais de duas semanas.
  • O painel Accessibility mostrar no meu menu ou diálogo um nome ou foco que eu não consiga corrigir.

Nesse caso eu voltaria ao Bootstrap só com a folha de estilo, sem o script.

Fontes

  • Bootstrap, documentação oficial: Getting started, Introduction, seção "JS components" (getbootstrap.com/docs/5.3/getting-started/introduction).
  • Grant, CSS in Depth: tema consultado, organização do CSS e propriedades personalizadas.
